## 3. 历史问题与修复记录（你关心的“哪里错了”）

### 问题 A：严格编译规则触发旧夹具失配（已修复）
- 现象：
  - 全量回归曾出现 `10` 个失败，集中在：
    - `tests/flow-engine.test.mjs`
    - `tests/flow-modules.test.mjs`
- 预期：
  - 标准流程应包含 `playAudio -> countdown -> playAudio ...` 等完整步骤链。
- 实际：
  - 由于测试数据里存在空音频 URL、空题组小题，严格编译会跳过步骤，导致链路变短（例如只剩 `intro/countdown`）。
- 根因：
  - 编译器规则已升级为“无效字段即跳过步骤”，但旧测试夹具仍是“宽松数据”。
- 修复：
  - 调整夹具为有效音频与有效小题数据。
  - 提交：`63a5fde`

### 问题 B：路由断言与新 UI 行为冲突（已修复）
- 现象：
  - `tests/flow-profile-routing.test.mjs` 里有断言“不应包含自动修复建议”导致失败。
- 预期：
  - 既要保留脚本层诊断能力，也要允许在 UI 展示路由模拟与修复建议。
- 实际：
  - 代码已恢复诊断面板，该断言过时。
- 修复：
  - 更新断言为匹配当前产品行为（包含“路由模拟器/路由规则诊断/自动修复建议”）。
  - 提交：`105222f`

### 问题 C：自动矩阵阈值过高（已修复）
- 现象：
  - 矩阵测试初版要求 `>=160` 场景，实际自动生成 `114` 场景，导致失败。
- 预期：
  - 测试保证“显著高于手工穷举”并稳定可重复执行。
- 实际：
  - 114 场景已满足覆盖目标，但阈值设置不合理。
- 修复：
  - 阈值调整为 `>=100`，保留自动组合 mutation 机制。
