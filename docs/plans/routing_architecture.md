# 流程路由架构 v1（地区单维）

更新时间：2026-02-26

## 1. 当前定版范围

本期只做“地区 -> 流程线”映射，不做跨区体验、不做子区域特例。

- 一个流程线可绑定多个地区。
- 一个地区只能绑定 1 个流程线。
- 未绑定地区统一走标准流程。

## 2. 题库 / 流程 / 路由职责

1. 题库：只维护题目内容，不按地区复制题目。
2. 流程：按题型维护多条流程线（如 听后选择-标准/成都/北京）。
3. 路由：按用户地区把题型请求映射到某条流程线。

结论：路由决策权在服务端，编辑器只负责配置与可视化。

## 3. 编辑器落地（已调整）

流程页已收敛为“流程编辑 + 地区匹配勾选”：

- 移除复杂路由大面板（region/scene/grade 多维评分）。
- 在流程图下提供“地区匹配”勾选区。
- 勾选某地区 = 该地区绑定当前流程线。
- 取消勾选 = 该地区回退到标准流程。

实现上仍复用 `flowProfiles` 存储，但会自动归一化为“仅地区规则模型”。

## 4. 规则约束

服务端必须保证：

1. `questionType + region` 至多 1 条生效规则。
2. 每个 `questionType` 必须存在默认规则（标准流程）。
3. 规则只能引用已发布流程线。

## 5. 服务端接口建议

`POST /api/flow/resolve`
- 入参：`questionId`, `questionType`
- 服务端内部读取用户 `region`
- 出参：`{ moduleId, moduleVersion, matchedRuleId, source }`

`GET /api/flow/modules?questionType=listening_choice`
- 查询流程线列表

`GET/POST /api/flow/rules/v1`
- 管理 `questionType + region -> moduleRef` 映射

## 6. 示例（听后选择）

流程线：
- 听后选择-标准
- 听后选择-成都
- 听后选择-北京

规则：
- `chengdu -> 听后选择-成都`
- `beijing -> 听后选择-北京`
- `default -> 听后选择-标准`

命中：
- 成都用户命中成都流程
- 北京用户命中北京流程
- 其他地区命中标准流程

## 7. 规模价值（1W / 5W 题）

假设 5 个地区：

- 不做路由：
  - 1W 题需要按地区复制到约 5W
  - 5W 题需要复制到约 25W
- 做 v1 路由：
  - 题目规模保持 1W / 5W
  - 只维护流程线与地区映射

## 8. 已知限制

1. 不支持跨区体验（成都用户体验北京流程）。
2. 不支持子区域特例（高新区单独策略）。
3. 不支持场景/年级等精细化路由。

## 9. 后续演进方向（v2 以后）

在 v1 稳定后再评估：

1. 增加跨区策略字段（如 `paperRegionMode`）。
2. 增加子区域维度（如 `district`）。
3. 增加灰度发布、优先级链与回滚策略。
